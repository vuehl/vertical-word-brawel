# 宝可梦轻量版 · 微信竖屏小游戏

已将原来的飞机示例移出本项目，移植指定目录中的「青翠森林轻量版」。微信运行包由源码生成到 `minigame/`，构建后可直接用微信开发者工具打开本项目，无需启动电脑上的网页服务器。

Git 仓库保留源码、原始素材、构建工具、依赖锁文件及必要配置。`node_modules/`、`minigame/`、本地存档、备份、日志、个人微信配置及验收截图不提交；首次从 GitHub 拉取后，请先按「修改与构建」安装依赖并构建。

## 打开与游玩

1. 微信开发者工具导入 **本项目根目录** `D:\原始竖版字灵游戏`，不要只导入 `minigame`。
2. 使用保留的 AppID `wxa545e5ead35ffb1b`，项目类型为小游戏，点击编译。
3. 选择游客进入、初始伙伴，然后从首页开始冒险。首次进入需下载并解压分包，请等加载完成。

手机预览请在 **本目录对应的「宝可梦森林竖屏版」窗口** 点击预览。同一 AppID 还用于其他本地工程，扫码前应核对开发者工具中的项目目录；如果看到「请旋转手机」或登录卡片挤在右侧，说明收到的画面与当前竖屏运行包不一致。完全退出手机中的小游戏，清理本工程的**编译缓存**，重新预览并扫描新码，无需删除游戏存档。

推荐在本目录运行 `npm run preview`：它会先构建，清理本工程的编译缓存，再指定当前目录生成二维码，保存到 `验收/手机预览/预览二维码.jpg`。首次使用前需要按下文安装 `tools/` 构建依赖；若微信开发者工具安装在其他位置，可通过 `WECHAT_DEVTOOLS_CLI` 指定 `cli.bat` 路径。此命令不清理存档，也不执行正式上传。

固定竖屏：左下摇杆移动，右侧空白区域拖动调整镜头；战斗自动攻击，右下保留原版技能、捕获等按钮。左手移动和右手转镜头可以同时操作。右上按钮暂停；角色详情、升级选项和结算内容可上下滑动。界面避开刘海、微信胶囊和底部安全区。

## 移植范围

- 保留原版 3D 场景、青翠森林三区与圣地、敌人与 Boss。
- 保留妙蛙种子、小火龙、杰尼龟三个初始伙伴，各自两次进化、技能、升级、捕获、难度、实验室与结算规则。
- 原轻量版的角色限制保持一致：151 组战斗素材不表示可以选择 151 个伙伴；可选及捕获范围仍由原版三伙伴规则控制。
- 使用微信本地文件保存进度，存档文件为 `wx.env.USER_DATA_PATH/pokebonk-save.json`，另有 `.bak` 备份。电脑原存档未自动导入。清除微信本地数据会同时清除该设备上的进度。
- 原版单机规则、数值表和资源均保留在 `source/`。没有新增联机、排行榜或云同步。

界面为了竖屏重新排布，原本较长的署名区改为可展开。角色图片使用无损压缩，模型保持原文件内容。为控制小游戏包体，运行包只携带轻量版会用到的资源，音乐与叫声转成 44.1 kHz / 56 kbps AAC；未转码的原始音频和未打包资源仍在 `source/`。

## 修改与构建

首次拉取或需要修改源码时，使用 Node.js 22 或更新版本。首次构建会自动生成资源包，需要 Python 与 `fonttools`；默认 Windows 使用 Python 3.13，也可通过 `POKEBONK_PYTHON` 指定已安装 `fonttools` 的 Python 可执行文件。在本目录执行：

```powershell
npm ci --prefix tools
py -3.13 -m pip install fonttools
npm run build
```

修改布局后，先运行 `npm run layout`，再运行 `npm run build`。布局生成需要本机 Chrome，可用 `CHROME_PATH` 指定路径；默认使用 `C:/Program Files/Google/Chrome/Application/chrome.exe`。

修改资源后运行 `npm run build:assets`。FFmpeg 随构建依赖提供。已有本地 `minigame/` 运行包时，只打开微信开发者工具游玩不需要重新安装构建依赖。

```powershell
npm test
npm run verify:assets
$env:POKEBONK_QA = Join-Path (Get-Location) '验收\竖屏'
npm run test:touch
npm run test:menus
npm run test:ui-perf
```

`npm run test:touch` 在 Chrome 中运行实际小游戏打包入口和微信 API 测试替身，检查不同尺寸布局、触摸、暂停、升级与存档；不是微信真机测试。`npm run verify:source` 对照记录中的桌面来源核验文件，原目录需要仍然存在。

`npm run test:menus` 检查研究所强化、道具筛选及设置的七个标签，覆盖 320、390、430 像素宽度，验证文字、按钮和卡片边界、列表滚动及音量滑块保存。菜单修复画面位于 `验收/页面重叠修复/`。旧版本滑块误存的 `8100%` 等音量值会自动恢复为正常百分比，无需清除存档。

纯软件渲染环境可用 `npm run test:touch -- --software-render` 降低测试中的 3D 帧率与场景分辨率，界面仍按原分辨率检查。该参数只作用于测试，不会改变小游戏运行包。

`npm run test:ui-perf` 检查登录、选伙伴和首页的排版次数、文字测量、UI 纹理上传与转场遮罩。它使用 Chrome 和微信 API 测试替身，输出的是工作量计数，不能当作苹果手机帧率。报告目录同样由 `POKEBONK_QA` 指定。

微信版界面只在内容、尺寸或滚动变化时重新排版；角色动画复用布局和 GPU 纹理。移除了不受原生 Canvas 支持的网页转场遮罩及固定等待，菜单背景上限为 30 帧、战斗上限为 60 帧。3D 场景使用 90 万像素、最高 1.5 倍采样的预算，并保留动态分辨率；界面仍独立使用较高分辨率，保证文字清晰。
