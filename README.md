# 字行 · 微信竖屏小游戏

以「青翠森林轻量版」为玩法基础，美术现已改为参考图的桌面微缩世界：蓝色裁切垫、点阵纸、横线笔记本与巨型文具；原有三区及圣地依次呈现为胶佬工作台、手帐漫游、文具高塔、字灵书庭。首页、选字、地图、难度、战斗信息、升级、进阶、老虎机、暂停、结算、属性、研究所与设置采用统一纸张与墨线设计。微信运行包由源码生成到 `minigame/`，构建后可直接用微信开发者工具打开本项目，无需启动电脑上的网页服务器。

## 精致档角色清晰度修正（2026-11-09）

修复精致档仍启用动态分辨率、从流畅切换时继承低倍率的问题。精致现在立即恢复倍率 1 并关闭自动降分辨率；保留原有最高 2 倍和 180 万场景像素预算、阴影与光效。均衡和流畅仍可动态降低场景分辨率。当前纸张版不再读取旧版隐藏的像素化设置；明确选择均衡或精致会关闭省电模式，之后主动开启省电仍临时使用流畅画质，实际生效状态会显示在设置页。

复现条件为 390×844、设备像素比 3，先将流畅档降至 0.6，再切换精致：修复前场景只有 468×1012，修复后立即恢复 780×1688。在模拟持续低帧率、手动缩放和旧存档 `pixel=3` 的检查中，精致仍保持该分辨率；均衡的自动缩放继续生效。固定精致清晰度会保留更多渲染工作量，低性能设备可能降低帧率。

本次未修改角色素材。此前角色图集合批前后均使用 192×192 字形，每个字形占图集的区域也保持 192×192；文具模型此前确实做过全档共享的圆柱减面，但与角色贴图尺寸无关。56 项基础测试、三种屏宽的画质／文字一致性及清晰度专项通过。对照截图和报告在 `验收/精致角色清晰度-20261109/`；复现命令为 `node tools/runtime-performance.mjs --clarity`，环境是 Chrome 微信 API 替身。

## 大招后的升级衔接与弹框（2026-11-09）

升级不再把大招暂停在半途。释放大招后，升级选择至少等待 1.5 秒，同时等待大招主体计时结束，再留出 0.2 秒收尾；期间经验、升级次数和大招伤害照常结算。单人模式在有待选升级的等待期间保留短暂无敌保护。暂停和切后台不消耗等待时间，普通升级仍先展示完整经验环。

升级窗口用 240 毫秒淡入、140 毫秒淡出。连续升级与重抽保留遮罩，避免返回战斗一帧再突然弹出；强化只在淡出完成后应用一次，快速连点不能重复领取。窗口、遮罩和静止战场各自复用 GPU 纹理，动画只调整透明度和位置；静止战场缓存于恢复游戏后释放。选择 60 帧时，动画按 60 帧目标运行；选择 30 帧或省电模式仍遵守 30 帧限制。

`npm run test:upgrade` 验证三种字灵、320／390／430 宽度、慢速首帧准备、重抽、连续两次升级、快速连点和实际主循环。受控开局中，火／水／木从释放到弹框分别约为 1.62／2.82／2.02 秒；水的大招主体本身持续 2.4 秒，未强行截断到两秒。三种尺寸的弹框准备后都没有重复整屏布局、文字纹理上传或战场渲染。实际主循环另采样 650 毫秒、17 次界面绘制，战斗更新与 3D 重绘均为 0；这些是 Chrome 微信 API 替身的工作量检查，不是真机帧率承诺。

本轮 56 项基础测试及 95 张界面截图回归通过，覆盖返回战斗、属性页、重抽、进阶、结算与触摸操作；正式包和独立开发包均构建成功。报告与截图位于 `验收/大招升级过渡-20261109/`。

## 启动页与文字清晰度（2026-11-09）

启动页采用与首页一致的奶油纸张、蓝色裁切垫、文具和火／水／木字灵纸片。美术由原生 Canvas 绘制，无需等待图片或字体下载；百分比仍来自真实下载与初始化进度，首页首帧完成后才显示 100%，随后释放启动纹理。

界面、按钮与 HUD 文字独立于场景画质，始终使用原精致档的清晰度（最高 2 倍、200 万像素）；流畅、均衡、省电模式与动态降分辨率只降低场景的渲染分辨率。低画质现在会比之前保留更多界面像素，但继续复用界面缓存和 HUD 小区域纹理。画质设置页增加了性能说明，小屏可滚动阅读。

在 390×844、设备像素比 3、动态分辨率为 1 的编译包检查中：

| 画质 | 场景分辨率 | 相对精致减少的场景像素 | 界面分辨率 |
| --- | --- | --- | --- |
| 精致 | 780×1688 | — | 780×1688 |
| 均衡 | 585×1266 | 43.75% | 780×1688 |
| 流畅 | 390×844 | 75% | 780×1688 |

这是渲染工作量，不是真机 FPS 提升。配置中的场景像素预算分别为 180 万／90 万／36 万（减少 50%／80%），实际分辨率还受屏幕、像素比和动态缩放限制。低画质还会减少阴影、光效、粒子和远处怪物更新的开销；怪群运算、设备温度与帧率上限仍会影响流畅度。省电模式上限为 30 帧。

55 项基础测试通过；`node tools/runtime-performance.mjs --quality` 验证 320／390／430 三种屏宽的三档画质、省电及恢复、动态缩放、文字像素一致性和说明滚动。`node tools/smoke.mjs --phone-layout --software-render --boot-only` 验证真实加载进度和首页交接。报告、截图保存在 `验收/加载页与清晰文字-20261109/`，测试使用 Chrome 微信 API 替身。

建议按下列顺序推进，分别测试收益：

1. **HUD 小块更新和纹理上传。** 已独立更新头像、血条、小地图和摇杆，但金币、积分、技能蓄能等变化仍可能触发整屏 UI。继续拆分常变计数器和技能区域，避免密集击杀时频繁排版、绘制并上传整屏。桌面 600 怪受控样本中，90 次更新有 6 次整屏上传，含其他 UI 图层合计约 14.8 MB；整屏排版每次平均约 4.6 ms。该样本只说明更新路径仍有开销，不能解释所有手机卡顿。
2. **透明特效、怪物阴影和飘字。** 密集怪物的本体面数低，但同一像素会被许多半透明层重复绘制。已有总预算之外，可继续按屏幕区域限制普通粒子密度、合并同一目标的伤害数字、降低流畅档怪群阴影密度；保留首领危险提示。用相同时间、怪数和画质作真机对比。
3. **怪群 CPU 工作量。** 敌人网格每帧仍清空并扫描 142×142=20,164 个格子，即便大部分为空；范围查询还逐格遍历。可改为活动区域网格或占用区间，保留完整命中结果。纸张地形的高度恒为零，仍走四点高度插值，可增加经过四区验证的平面快速路径。远怪分帧和推挤采样已经存在，不应以跳过伤害判定代替优化。
4. **按字形合并角色绘制。** 纹理已按字形共享，实例批次仍按原角色编号建立。可进一步按字形／兼容材质合批，保留各角色自己的碰撞尺寸、属性与状态。这主要减少绘制调用；[Three.js 官方合批说明](https://threejs.org/manual/pages/optimize-lots-of-objects.html)解释了大量独立 Mesh 的提交成本。
5. **再精简圆柱和道具材质。** 先减装订杆、笔杆等细小圆柱，再考虑互动道具多个零件的材质合并。宝箱开盖、圣地可破坏部件必须保留独立变换。静态场景已经实例合批，不能把“合并所有模型”当作还没做过的优化。

第一关普通难度的导演目标上限按当前公式在 2／3／5／8 分钟约为 106／168／318／610，最终还受实体上限和动态调节限制；实际存活数量还受击杀与事件影响。复现手机两分钟卡顿应先测试 2 分钟＋100／200 怪，再用 400／600 怪做压力测试。先使用流畅档、30 帧、关闭伤害数字作对照，再逐项恢复设置，记录两分钟和十分钟后的实际帧率与发热情况。

桌面基线中敌人更新平均约 0.40 ms（200 怪）／0.65 ms（600 怪）；完整帧还含 GPU、驱动、UI、上传和等待，不能把这两个数字换算为手机帧率，也不能据此保证优化后手机不卡。原始阶段计时和 CPU 采样位于 `baseline/`。

## 修改与构建

首次拉取或需要修改源码时，使用 Node.js 22 或更新版本。首次构建会自动生成资源包，需要 Python 与 `fonttools`；默认 Windows 使用 Python 3.13，也可通过 `POKEBONK_PYTHON` 指定已安装 `fonttools` 的 Python 可执行文件。在本目录执行：

```powershell
npm ci --prefix tools
py -3.13 -m pip install fonttools
npm run build
```

新版字行界面由原生弹性布局计算，修改布局后运行 `npm run build` 即可；`npm run layout` 仅用于旧界面的参考尺寸。测试需要本机 Chrome，可用 `CHROME_PATH` 指定路径；默认使用 `C:/Program Files/Google/Chrome/Application/chrome.exe`。

原始字形保存在 `source/art/glyphs/`。修改字形后先运行 `node tools/glyph-atlas.mjs`，再运行 `npm run build:assets`。其他资源修改后也运行 `npm run build:assets`；该命令同时更新 `source/src/actor-metrics.js` 的碰撞尺寸，请一并提交。首次更新到中文精简版时，也需要运行一次 `build:assets`，避免混用旧资源包。当前手机版不打包背景音乐，无需转换音频。已有本地 `minigame/` 运行包时，只打开微信开发者工具游玩不需要重新安装构建依赖。

当前资源筛选规则在 `tools/asset-policy.mjs`，道具生成清单由 `source/src/paper-prop-names.js` 与运行时共享。普通 `npm run build` 会检测资源策略版本并自动更新旧包；修改筛选或分包规则时递增 `assetPolicyVersion`。开放其他地图、活动、角色或旧社交界面前，需同步复核排除规则并重新生成资源。资源核验会检查当前地图、活动范围和必要共享素材，防止只改入口却遗漏资源。

2026-11-09 字灵资源与绘制合批优化：策略版本升至 3，从运行包排除已统一替换为字灵画布的 304 张旧头像和图标；原始动画素材仍用于构建时的碰撞尺寸核验，源码素材不需要删除。当前资源映射从 577 项降至 273 项，角色与道具美术包从 541,090 降至 264,824 字节（减少 51.1%）；整体运行包从 12,140,534 降至 11,849,898 字节（11.58 → 11.30 MiB）。完整排除原因及各分包体积由 `npm run build:assets` 写入 `验收/资源打包清单.json`。音乐仍按曲目加载，当前道具、地图提示、危险区域、字体和玩法数据保留。
